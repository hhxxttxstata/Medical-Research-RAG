架构分级

级别名称关键特征
L0可运行原型核心路径可走通，无测试、无异常处理

差距维度速查

🔴 P0 可观测性

  • Metrics：Prometheus + Grafana
  • 请求量、p50/p95/p99、错误率
  • 检索召回率、Agent 步数分布
  • Tracing：OpenTelemetry
  • HTTP → 分类 → 检索 → LLM → 回复
  • Logging：structlog / loguru
  • JSON 格式、可查询、有 trace_id

🔴 P0 安全与认证

  • API Key 认证（Bearer Token）
  • Rate Limiting（slowapi / 令牌桶）
  • Pydantic v2 严格输入校验
  • Prompt Injection 检测
  • CORS 白名单（非 *）
  • 敏感信息脱敏（API Key）

🔴 P0 CI/CD

  • GitHub Actions：push → test → lint → build
  • Pre-commit hooks：ruff + mypy
  • Docker 构建 + trivy 安全扫描
  • 自动部署（可选）

🟡 P1 Agent 生产化

  • SSE 流式输出 Thought/Action/Obs
  • 异步 async/await Agent 循环
  • Guardrails（输出检查、PII 过滤）
  • Tool 元数据：parallel_safe, timeout, retry

🟡 P1 RAG 生产化

  • 增量索引（watchdog 监听文件变更）
  • 多级缓存：embedding / 检索 / LLM
  • Cross-encoder reranker（bge-reranker-v2）
  • 多集合、文档标签、版本管理

🔵 P2 工程基建

  • pyproject.toml 统一配置
  • Pydantic BaseSettings 配置中心
  • httpx 连接池
  • BM25 索引序列化到磁盘
  • Docker 多阶段构建

面试要点

  • 🎯 先讲优点（自实现 ReAct、三层记忆、评估管线、优雅降级）
  • 📊 再讲差距（可观测性、安全、CI/CD、流式输出）
  • 💡 附改进方向（按 P0/P1/P2 优先级排序）
  • ✅ 强调从 L1 → L2/L3 的具体路径，而非停留在"意识到了问题"
  • 🚫 避免：过度批评自己的代码、贬低已有工作、承诺不切实际的时间线
