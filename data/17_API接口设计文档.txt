RAG 系统 API 接口设计文档
==========================

一、接口概述
-----------
本 API 提供 RAG 系统的核心功能，包括文档管理、检索查询和系统管理三类接口。
所有接口采用 RESTful 设计风格，请求和响应格式均为 JSON。

二、文档管理接口
---------------
1. POST /api/v1/documents/upload
   上传文档到知识库
   参数：file（multipart/form-data）
   返回：{"document_id": "doc_001", "status": "processing"}

2. GET /api/v1/documents/
   获取文档列表
   返回：{"documents": [{"id": "doc_001", "filename": "...", "chunks": 15}]}

3. DELETE /api/v1/documents/{document_id}
   删除指定文档及其所有 Chunk

三、检索查询接口
---------------
1. POST /api/v1/query
   提交查询
   请求体：{"query": "肺结节的CT影像特征是什么？", "top_k": 5}
   返回：{"answer": "根据检索到的文档...", "sources": [...]}

2. POST /api/v1/query/stream
   流式查询，通过 SSE（Server-Sent Events）返回数据
   事件类型：token（逐字输出）、source（引用来源）、done（完成）

3. GET /api/v1/retrieve
   仅检索不生成回答
   参数：query（字符串）、top_k（整数，默认5）
   返回：{"results": [{"chunk": "...", "metadata": {...}, "score": 0.95}]}

四、系统管理接口
---------------
1. GET /api/v1/system/status
   获取系统运行状态
   返回：{"status": "healthy", "doc_count": 15, "chunk_count": 120}

2. POST /api/v1/system/reindex
   重新索引所有文档
   返回：{"status": "reindexing", "estimated_time": "2 minutes"}

五、错误码说明
-------------
| 状态码 | 说明              | 处理建议               |
|--------|-------------------|------------------------|
| 200    | 请求成功          | 正常处理响应           |
| 400    | 请求参数错误      | 检查请求参数格式       |
| 404    | 资源不存在        | 检查资源 ID 是否正确   |
| 413    | 文件过大          | 文件大小限制为 50MB    |
| 429    | 请求频率超限      | 降低请求频率           |
| 500    | 服务器内部错误    | 联系系统管理员         |
