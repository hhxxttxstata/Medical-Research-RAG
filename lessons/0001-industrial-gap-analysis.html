Lesson 1: 差距全景图

你的 RAG/Agent 系统离工业级还差多远？一张路线图讲清楚

🎯 本课目标：建立工业级 RAG/Agent 系统的完整认知框架，找出当前项目与工业级的差距，制定可执行的升级路径。学完这课，你可以在面试中讲清楚"我的系统目前处于什么阶段，下一步怎么走"。

一、先看定位：你的系统属于什么阶段？

工业级系统能力分级（参考 Fowler 生产就绪定义 + SEI 成熟度模型）：

等级名称特征你当前
L0可运行原型能跑通一条路径，但健壮性差、无测试、无异常处理—
L1功能完整核心功能完整、有测试、有错误处理、结构清晰✅ 你在这里
L2可部署Docker 化、健康检查、优雅关停、配置管理部分
L3可运维Metrics + Tracing + 告警、日志中心化、CI/CD❌
L4可观测APM 分布式追踪、SLO 监控、A/B 测试、金丝雀发布❌
L5自适应自愈、自动扩缩容、反馈闭环、模型在线学习❌

注意：L4-L5 通常只有大型团队才需要。对秋招项目，L2-L3 是合理的上限——超出太多面试官反而会怀疑深度。

你的系统目前处于 L1 → L2 过渡期。核心功能齐全（RAG、Agent、诊断、记忆、评估），但基础工程化缺失。这不是你的问题——它反映了绝大多数学术/个人项目的真实状态。接下来我们要做的就是针对性地补上缺失的工程化拼图。

二、全景差距分析

以下七大维度，按优先级排序：

🔴 P0 — 缺失即不可用

1. 可观测性体系 P0

影响: 线上问题排查时间从分钟级变成小时级

现状：只有 JSONL 文件日志（logger.py），无结构化指标、无链路追踪、无告警机制。

工业级做法：

  • Metrics — Prometheus + Grafana：请求量、延迟分位数 (p50/p95/p99)、错误率、检索召回率、Agent 步数分布
  • Tracing — OpenTelemetry：每次查询从 HTTP 入口 → 意图分类 → 检索 → LLM 调用 → 回复，全链路追踪
  • Structured Logging — 将当前 print() 日志替换为 structlog 或 loguru，JSON 格式、可查询

面试价值："可观测性"是秋招高频考点。能讲清楚 Metrics/Tracing/Logging 三者的区别和实现，加分明显。

2. 安全与认证 P0

影响: 当前任何知道你 IP 的人都可以调用所有 API

现状：allow_origins=["*"]，无 API Key 认证、无速率限制、无输入校验。

工业级做法：

  • API Key 认证 — FastAPI Depends() 或中间件，Bearer token 验证
  • Rate Limiting — slowapi / 令牌桶算法：不同 endpoint 不同配额
  • 输入校验 — Pydantic v2 严格模式 + prompt injection 检测（关键词/向量相似度）
  • CORS 收紧 — 允许特定域名而非 *

面试价值：安全设计体现生产意识。"我的系统在生产前会补全认证和限流"——比"我不知道"好一百倍。

3. CI/CD 流水线 P0

影响: 每次改代码都需要手动测试→部署，容易遗漏

现状：无 .github/ 目录、无自动化流程。

工业级做法：

  • GitHub Actions：CI — 每次 push 跑 pytest + lint + type check
  • Pre-commit hooks：black/ruff 格式化、mypy 静态检查
  • Docker 构建：CI 中自动构建镜像 + 安全检查（trivy）
  • CD 可选：push 到 main 自动部署到测试环境

面试价值：DevOps 流程是"全栈能力"的体现，也是面试常问项。

🟡 P1 — 当前功能可升级

4. Agent 生产化 P1

影响: Agent 调用时间长、无流式反馈、无行为约束

现状：ReAct 循环同步阻塞调用，无流式输出，无 Guardrails。工具调用在 ThreadPoolExecutor 中并行但整体仍阻塞请求。

工业级做法：

  • SSE 流式输出 — 将 ReAct 的 Thought/Action/Observation 实时推送给前端展示，而非等全部完成后一次性返回
  • 异步 Agent 循环 — async/await 改造，配合 FastAPI 的异步处理，避免阻塞事件循环
  • Guardrails — 工具调用前的安全检查（输出是否含 PII？是否调用了危险 shell 命令？）
  • Tool 注册表优化 — 当前 Tool 基类设计好，但缺少 parallel_safe、retry_policy、timeout 等元数据

面试价值：Agent 是 2026 年面试绝对热点。从"功能实现"到"生产化"的思考深度，能让你在面试中脱颖而出。

5. RAG 生产化 P1

影响: 每次改数据需重建索引，无缓存，响应慢

现状：知识库只初始化一次，新增文档需要手动 --rebuild。每次查询都走全量检索→LLM。

工业级做法：

  • 增量索引 — 监听目录变化（watchdog），新文件自动加载、分块、embedding、入库
  • 多级缓存 — Embedding 缓存（相同 query 缓存向量）、检索结果缓存（LRU）、LLM 回答缓存（语义相似查重）
  • 高级 reranker — 当前用 LLM 做 reranker 太昂贵，改为 cross-encoder 模型（如 BAAI/bge-reranker-v2）
  • 知识库管理 — 支持多集合、文档标签、版本管理

面试价值：RAG 是面试必考。能说出"我的系统做了 XX 优化来解决 YY 问题"比背八股好一百倍。

🔵 P2 — 锦上添花

6. 工程基础设施 P2

影响: 开发体验差、代码质量难保障

现状：requirements.txt 传统模式、无 pyproject.toml、无 pre-commit、无配置管理。

工业级做法：

  • pyproject.toml — 统一管理依赖、工具配置（pytest、ruff、mypy）
  • Pre-commit hooks — ruff lint + format、mypy type check、pytest smoke test
  • 配置中心化 — 将 .env + 构造函数参数 统一为 Pydantic BaseSettings
  • 日志规范 — 统一日志格式、支持 JSON 输出、日志级别动态调整

7. 性能优化 P2

影响: 大负载下响应时间会劣化

现状：无连接池、无缓存、BM25 每次检索都重建索引。

工业级做法：

  • HTTP 连接池 — httpx.Client() 重用而非每次新建
  • Embedding 批量缓存 — diskcache 缓存已计算的文档 embedding
  • BM25 索引持久化 — 当前在 _ensure_bm25_index 中从 get_all_documents() 懒构建，每次都重新分词。改为序列化到磁盘
  • 并发控制 — 当前 ThreadPoolExecutor 固定 4 个 worker，可改为根据负载动态调节

四、优先级的思考逻辑

为什么 P0 是那三个？：

优先级选它的原因面试官会问吗？
P0 可观测性 没有监控，出了问题你根本不知道。这是生产系统和玩具的分水岭。 ✅ "你的系统怎么保障线上质量？"——必问
P0 安全认证 FastAPI 默认裸奔，* CORS 意味着任何网站都能调你的 API。 ✅ "你的系统有安全考虑吗？"——常问
P0 CI/CD 没有自动化流程，改代码靠手测，协作靠信任。一个 commits 就能崩掉整个系统。 ✅ "你们项目的 CI 怎么设计的？"—项目中高级问题
P1 Agent 生产化 Agent 是核心亮点，但是同步模式。流式 + 异步是现在业界标配。 ✅ "你的 Agent 推理过程用户等多久？"—常问
P2 工程基建 开发体验改善、代码质量保障。不影响线上但影响团队效率。 ❌ — 但如果你主动提，能显示工程视野
💡 面试话术示例：
"我的项目目前处于功能完整阶段（L1），核心流程都已走通。但距离工业级部署还差几个关键环节：第一是可观测性——目前只有日志，我计划引入 Prometheus 指标和 OpenTelemetry 链路追踪；第二是安全认证——需要加上 API Key 和限流；第三是 CI/CD——实现自动化测试和构建。这些是我下一步的重点方向。"

五、回顾：你的系统的核心优势

在开始批评之前，先看看你做对了什么（面试中也要先讲优点）：

  1. 架构清晰 — 模块化设计合理（agent.py、rag_pipeline.py、retriever.py、memory.py 各司其职），比很多 starter template 好得多
  2. 自实现 ReAct 循环 — 不依赖 LangChain，能用面试语言解释清楚每个环节。这是很大的加分项
  3. 三层记忆系统 — 短期+工作+长期的分解展示了系统性思维，工业级 Agent 的标准架构
  4. 完整的评估管线 — 7 个评估文件、LLM-as-Judge、检索质量测试。大多数项目根本没有这个
  5. 优雅降级 — Function Calling → ReAct → 规则兜底的链路设计，LLM 不可用时系统不崩溃
  6. MCP 协议支持 — 这是一个前沿方向，能体现你关注行业动态
  7. 诊断模型集成 — RAG + 诊断模型推理 + Agent 的融合架构
  8. 中文+医学领域适配 — 中文 Bigram 重叠、中英分词、e5 模型特定 prefix
🔑 核心信息：
你的系统在"功能"层面已经达到甚至超过了很多秋招项目。缺失的是"工程化"——这是认知层面的差距，不是能力层面的差距。一旦你意识到需要补什么，你完全有能力补上。
